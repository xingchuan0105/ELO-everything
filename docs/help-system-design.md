## 1. 目标与原则

### 1.1 目标

1. **破冰**：首页显眼入口，用讲故事方式解释「什么是 ELO 积分」。
2. **会用**：完整「如何使用本应用」说明，对齐真实页面与流程。
3. **随手懂**：关键概念旁有注释小标；悬停看摘要，点击跳到帮助正文对应章节。
4. **不吓人**：避免公式堆砌；需要时用「大概」「好比」再附可选「想多了解一点」。

### 1.2 原则

| 原则 | 说明 |
|------|------|
| **故事优先** | 起源 → 为什么需要 → 怎么涨跌 → 用在哪，再谈本产品 |
| **双层解释** | 短：tooltip（1–3 句）；长：帮助文档章节 |
| **同一套词表** | 界面、tooltip、帮助文档用同一中文名（见 §3 术语表） |
| **可锚定** | 每个概念有稳定 `id`，支持 URL hash 跳转 |
| **渐进披露** | 首页只推「故事」；工作台推「操作」；参数旁推「这一项」 |
| **记录员视角** | 读者是记分的人，不是选手 |

### 1.3 非目标（本设计阶段）

- 不做多语言 i18n 完整体系（先中文）。
- 不做站内搜索引擎级检索（可做目录 + 锚点 + 简单关键词索引表）。
- 不替代客服工单系统。

## 4. 内容规格

### 4.1 故事篇：`/help/elo` —「什么是 ELO 积分？」

**定位**：像讲故事，10–15 分钟可读完；不懂棋也能懂。  
**结构（固定章节 id）**：

| 章节 id | 标题 | 内容要点 |
|---------|------|----------|
| `#origin` | 故事从国际象棋说起 | 阿帕德·埃洛（Arpad Elo）为棋手排名设计；后来被游戏、体育广泛借用 |
| `#why` | 为什么需要「积分」而不是只数胜场？ | 只数胜场不公平：总打新手 vs 总打高手；需要「赢强的多涨、赢弱的少涨」 |
| `#number` | 一个数字，代表什么？ | 积分是**相对**强弱：1500 不一定「等于」某段，关键是和对手比差多少 |
| `#how` | 一场比赛后，分数怎么变？ | ① 先根据双方积分估计谁更可能赢 ② 若结果「意外」，分数变动更大 ③ 步长 K 控制「一场能抖多狠」——**不写公式**，可用表格举例 |
| `#example` | 小例子 | 甲 1500 vs 乙 1500，甲赢 → 双方各动约 K/2；甲 1800 vs 乙 1200，甲赢 → 甲几乎不涨、乙少跌；乙爆冷赢 → 乙大涨、甲大跌 |
| `#where` | 还用在哪里？ | 电竞、桌上游戏、球类业余联赛、公司内部赛；本产品就是把这套思路做成「记录员工具」 |
| `#in-app` | 在 ELO-everything 里意味着什么？ | 你录入对局 → 系统按规则更新每位选手积分 → 排名表自动变；选手本人不必懂 ELO |
| `#limits` | 它不保证什么？ | 不是「绝对实力真理」；人少时抖动大；乱序录入会算歪（链到 guide#timing） |
| `#next` | 接下来 | 按钮：开始使用 / 阅读使用说明 |

**文案语气**：第二人称「你」；短段落；可穿插 1–2 个示意图位（天平 LOGO、涨跌箭头）。

**首页卡片文案草案**：

> **什么是 ELO 积分？**  
> 用一个会涨会跌的分数，公平地记录「谁更可能赢谁」。  
> 三分钟故事 →

### 4.2 使用篇：`/help/guide` —「如何使用本应用」

**读者路径**（与真实路由一致）：

| 步骤 id | 标题 | 对应产品界面 |
|---------|------|----------------|
| `#roles` | 你是记录员，不是选手 | 登录/注册 |
| `#login` | 注册与登录 | `/register` `/login` |
| `#create-event` | 创建一场赛事 | `/app` 创建表单 |
| `#add-players` | 添加选手 | `/app/events/[id]` → 选手 |
| `#score` | 登记对局（主/客、结果、时间） | 记分表 |
| `#timing` | **按真实时间顺序录入**（重点） | 记分表时序提示 |
| `#draft-publish` | 保存草稿 vs 发布更新排名 | 两个按钮 |
| `#rank` | 查看排名 | 排名页签 |
| `#pair` | （可选）辅助配对 | 配对页签 |
| `#void` | 录错了怎么办 | 历史/撤销 |
| `#checklist` | 一场完整比赛检查清单 | 汇总 |

**`#timing` 必须写清**（与引擎行为一致）：

1. 每位选手有一条积分时间线。  
2. 发布时按 **对局时间从早到晚** 一场一场算。  
3. 同一人先打 A 再打 B：打 B 时用的是打完 A 之后的分。  
4. 若把晚打的先录、时间却填成更早，排名会不符合现场。  
5. **建议**：现场记纸质/备忘时间，录入时与之一致；批量多行时默认时间已错开，仍请改成真实时间。

**`#draft-publish`**：

| 操作 | 用户话术 | 系统行为 |
|------|----------|----------|
| 保存草稿 | 「先记下来，先不算分」 | `status=draft`，排名不变 |
| 发布更新排名 | 「正式算分」 | 按时间链计分，排名变；失败整批回滚 |

#### 参数文案规格示例（实现时照此写全文）

##### 积分步长 K `{#k-factor}`

- **一句话**：控制「一场比赛，分数大概能跳多高」。  
- **有什么用**：K 大 → 排名反应快；K 小 → 更稳、要打更多场才拉开。  
- **怎么填**：创建赛事时填写；一般用默认即可。  
- **建议**：业余朋友局 **24–32**；希望别大起大落 **16**；娱乐向剧烈一点 **40**（勿超过 64）。  
- **偏大**：一场爆冷分差巨大，榜单「过山车」，新数据盖过长期表现。  
- **偏小**：打很多场分还差不多，难以及时反映状态。  
- **相关**：新手步长、新手保护场次。

##### 起始分 `{#start-rating}`

- **一句话**：新人（或新赛事）第一次出现的分数。  
- **有什么用**：只是尺子的零点附近；重要的是之后相对变化。  
- **建议**：**1500**（最常见）；想分数看起来「小一点」可用 1000/1200。  
- **偏大/偏小**：主要影响观感与跨赛事对比（本产品各赛事独立，不强制统一）。  
- **注意**：改起始分只影响**新选手/新赛事**，不会自动改写已开打的历史（v1 不追溯改配置）。

##### 新手步长 `{#k-provisional}`

- **一句话**：刚打前几场时，用更大的步长，让分数快点「找到位置」。  
- **建议**：比 K 略大，如 K=32 时用 **40**；且必须 ≥ K。  
- **偏大**：定级快但波动猛。  
- **偏小（接近 K）**：新手期意义不大。

##### 新手保护场次 `{#provisional-games}`

- **一句话**：用「新手步长」的场数；超过后改用普通 K。  
- **建议**：**10–30**；人少、想快点稳可用 10–15；希望多观察用 20–30。  
- **为 0**：从第一场就用普通 K。  
- **过大**：长时间分差剧烈，榜单像新号专场。

##### 对局时间 `{#played-at}`

- **一句话**：这场球**实际开打/结束**的时间，用来决定算分顺序。  
- **怎么填**：尽量贴近真实；批量录入时务必检查先后。  
- **填错顺序**：同一人的后续场会用错「当前分」，排名偏离现场观感。

（其余锚点同结构写满。）

## 5. 注释小标（Tooltip + 跳转）组件

### 5.1 视觉

- 名称：**帮助小标** / 组件名 `HelpTip`
- 形态：圆角小圆或方标内 **「?」**，铜色描边或浅灰底（对齐 monochrome ink + copper）
- 尺寸：约 16–18px 点击热区 ≥ 24px（移动端好点）
- 位置：标签文字右侧，如 `积分步长 K [?]`

### 5.2 交互

| 行为 | 桌面 | 移动 |
|------|------|------|
| 悬停 / 长按 | 弹出 **Popover**（短文案） | 点击弹出 |
| 点击小标本体 | 跳转 `/help/params#{anchor}`（新页或同页） | 同左 |
| Popover 内链 | 「详细说明 →」→ 同上锚点 | 同左 |
| 键盘 | Tab 聚焦 + Enter 打开/跳转 | — |

**不要**：仅 hover 无法跳转；必须可点进文档。

### 5.3 数据驱动（推荐）

集中配置，避免文案散落：

```ts
// packages/help-content 或 apps/web/content/help/tips.ts
export type HelpTipId =
  | "k-factor"
  | "start-rating"
  | "k-provisional"
  | "provisional-games"
  | "allow-draw"
  | "played-at"
  | "draft"
  | "publish"
  | "home-away";

export const HELP_TIPS: Record<HelpTipId, {
  label: string;           // 旁注标题
  summary: string;         // tooltip 正文 1–3 句
  href: string;            // /help/params#k-factor
  placement?: "top" | "bottom" | "left" | "right";
}> = {
  "k-factor": {
    label: "积分步长 K",
    summary: "控制一场比赛分数能跳多大。越大反应越快，越小越稳。朋友局常用 32。",
    href: "/help/params#k-factor",
  },
  // ...
};
```

使用：

```tsx
<label>
  积分步长 K
  <HelpTip id="k-factor" />
</label>
```

### 5.4 必须挂小标的界面位置

| 页面 | 字段 |
|------|------|
| `/app` 创建赛事 | K、起始分、允许平局、新手步长、新手保护场次 |
| `/app/events/[id]` 记分 | 对局时间（列头）、主/客（列头或表上说明）、保存草稿、发布更新排名 |
| 记分时序提示条 | 「时序规则」→ `#played-at` + guide `#timing` |
| 排名页（可选） | 「积分」「新面孔」徽章 → `#rating` / `#provisional-games` |

## 8. 无障碍与体验细节

- Tooltip：对比度达标；不要仅靠 hover 传达关键规则（时序规则在页面上也有常驻提示）。  
- 焦点顺序：标签 → 小标 → 输入框。  
- 跳转后：目标标题 `scroll-margin-top` 避开 sticky 顶栏；可短暂高亮章节。  
- 打印：帮助页可打印（可选）。

## 10. 验收标准

1. 未登录用户从首页 2 次点击内进入「什么是 ELO」并读完主路径。  
2. 创建赛事时，K/起始分/新手相关字段旁均有 `?`，悬停有摘要，点击进入 params 对应锚点且章节标题可见。  
3. 记分页「对局时间」旁可进入时序说明；guide `#timing` 与产品行为一致（链式、按时间发布）。  
4. 帮助内不出现未解释的英文缩写（首次可括注 ELO）。  
5. 移动端：注释可点开，链接可跳转，不依赖 hover。

## 11. 文案风格指南（给写手）

- 用「分数会动」「更可能赢」代替「期望得分」「概率模型」。  
- 数字例子优先于公式；公式可放在「想多了解一点」折叠。  
- 威胁/警告用中性句：「若时间顺序与现场不符，排名可能和你印象不一致。」  
- 每屏最多一个行动按钮主色。

## 12. 与现有产品行为的对齐检查表

| 帮助承诺 | 产品现状（实现时核对） |
|----------|------------------------|
| 草稿不算分 | `status=draft` |
| 发布按时间链计分 | `publish` order by `played_at` |
| 失败整批回滚 | 单事务 publish |
| K/起始分创建时设定 | `rules` on create |
